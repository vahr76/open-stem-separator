# OSS Downloader Core v0.2.0

This release starts the transition from a downloader-only asset to a local OSS song project model.

## Assets

- `ytd-0.2.0-linux-x64.tar.gz`
- `ytd-0.2.0-windows-x64.zip`

## What changed since v0.1.4

- Added `project.json` creation for every song project folder.
- Kept `metadata.json` as source/download metadata while introducing `project.json` as the stable OSS project manifest.
- Preserved future project fields when `project.json` already exists, including `media`, `stems`, `analysis`, `lyrics`, `exports` and `notes`.
- Documented the target OSS project folder contract in `docs/PROJECT_STRUCTURE.md`.
- Replaced generic install notes with release-package installation instructions in `docs/INSTALL.md`.
- Updated package names and build workflows to `0.2.0`.

## Why this is 0.2.0

During the pre-1.0 phase, MINOR versions are used for product-function or product-model changes. `project.json` changes the local model from “downloaded files in a folder” to “an OSS song project with a stable manifest”, while staying backward-compatible with existing downloads.

## Validation

Run from the repository before release:

```sh
python3 -m unittest discover -s tests -v  # 49 tests
gh workflow run build-linux.yml --ref main
gh workflow run build-windows.yml --ref main
```

Linux packages should still be smoke-tested with `docs/LINUX_PORTABILITY.md`.

## Release type

This is a MINOR release under the project versioning policy because it introduces the OSS project manifest foundation.
